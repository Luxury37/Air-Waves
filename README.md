# Air-Waves

> 清冷后朋克无线电风格的单页听觉节拍发生器。
> 用 Web Audio API 生成**双耳节拍 / 等时节拍**，为工作、学习时营造适合专注与放松的声音环境。

> 📖 **新手请先看 [START.md](START.md)** —— 功能与风格简介、下载与运行方法都在那份文档里，看完就能跑起来。
> 本文件是完整文档，包含音频实现细节、素材替换与背景图重新合成、以及已验证项。

**本工具仅用于放松与专注辅助，非医疗设备。** 不用于诊断、治疗或预防任何疾病。
双耳节拍对每个人的主观感受差异很大，如感到头晕、耳鸣或任何不适，请立即停止使用。

## 1. 本地运行

项目是纯静态页面（原生 HTML + CSS + JS，无构建步骤、无依赖、无后端），必须通过 **http 服务**打开，
不能直接双击 `index.html`（`file://` 协议下浏览器可能拦截部分资源）。

在项目根目录 `C:\Users\14793\Documents\Air-waves` 下任选一种：

```powershell
# 方式一：项目自带的 serve.py（推荐）
python serve.py 8765
# 然后浏览器打开 http://127.0.0.1:8765/
```

```powershell
# 方式二：标准库（能用，但见下方缓存提示）
python -m http.server 8765
```

```powershell
# 方式三：Node
npx --yes serve -l 8765 .
```

```powershell
# 方式四：VS Code
# 安装 "Live Server" 扩展 → 右键 index.html → Open with Live Server
```

> **为什么推荐 `serve.py`**：`python -m http.server` 只发送 `Last-Modified`、不发送 `Cache-Control`，
> 浏览器会对这类响应启用**启发式缓存**（按文件年龄的 10% 估算新鲜期，上限 24 小时）。
> 结果是改完 `app.js` / `audio.js` 后刷新页面，浏览器可能仍然用缓存里的旧脚本，
> 表现为"改了没生效"。`serve.py` 在此基础上强制加上
> `Cache-Control: no-store` 并移除 `Last-Modified`，彻底避免这个问题。

桌面快捷方式已自动使用 `serve.py`；如果你之前用 `python -m http.server` 打开过页面，
缓存里可能还留着旧脚本，**按一次 `Ctrl+Shift+R` 强制刷新**即可清掉，之后不会再出现。

打开页面后，点 **START / 开始** 进入播放界面（此时**不会自动播放**，停在待机状态），
再手动点 **PLAY** 才开始出声。

> 浏览器策略要求音频必须由用户操作触发。因此进入电台只是切换界面，
> 点 **PLAY** 时才建立 AudioContext 并开始播放，这是预期行为，不是卡顿。

### 音频听感建议

- **请佩戴耳机**。双耳节拍依赖左右声道差频，外放时左右声场混合，效果会明显减弱。
- 音量从 35% 起步，觉得合适再调；长时间使用建议低于 50%。
- 背景底噪（AMBIENT NOISE）是可选的粉红噪声，用于掩蔽环境杂音；
  蓝牙耳机下若听到编码噪点，打开它通常能明显改善（见 5.4）。

## 2. 功能

| 功能 | 说明 |
| --- | --- |
| 频段预设 | **Theta** Δf 7 Hz（载波 180 Hz）· **Alpha** Δf 10 Hz（载波 200 Hz，默认）· **Low Beta** Δf 15 Hz（载波 220 Hz） |
| Δf 微调 | 4–18 Hz 连续可调，界面读数与刻度指针实时同步 |
| 双耳模式 | 左耳载波，右耳载波 + Δf（默认 200 / 210 Hz） |
| 等时模式 | 左右同频，按 Δf 通断脉冲（幅度调制，脉冲率 = Δf） |
| 音量 | 0–100%，二次曲线映射，低音量区间更细腻 |
| 背景底噪 | 可选粉红噪声 + 低通，默认关闭 |
| 平滑过渡 | 播放 0.9 s 渐入、暂停 0.55 s 渐出、换频 0.6 s 滑音，全程无爆音 |
| 状态显示 | 频段名、Δf、左右载波频率、播放状态、已播放时长 |
| VU 表 / 波形 | 实时 RMS 电平条 + 时域波形示波器 |
| 后台播放 | 切到其他标签页 / 最小化后**继续发声**，不会自动暂停 |
| 键盘 | `Space` 播放/暂停 · `M` 静音 · `Esc` 返回首页 · `1/2/3` 切换频段 · `↑/↓` 音量 · `←/→` Δf |
| 响应式 | 桌面 / 平板 / 手机（含 320 px 窄屏）均无横向溢出，控件可点击 |

切到其他标签页或最小化窗口都会继续播放，只有按暂停 / 静音 / 返回首页才会停止。

### 4.2 播放页背景是"合成图"

播放页背景并不是直接用原始场景，而是把**透明人物合成进场景**后得到的一张成品图，
这样人物与场景的光影、颗粒、色调完全统一。页面上不再有单独的 `.figure` 图层
（`styles.css` 里 `.figure` 已设为 `display: none` 并保留作占位）。

合成做了三件事：

1. **暮色薄雾**：原始场景中下部有一条近纯黑的横带（亮度仅 2.7–7），
   直接裁掉会连白色轿车一起删掉，所以改为叠加一层按 `sin` 包络分布的冷色薄雾
   （加性混合，暗部提亮多、亮部几乎不动），把最暗行从 2.6 提到 38，保留全部内容。
2. **人物缩放与摆位**：人物实际高度（不含顶部透明边距）缩放到场景的约 65%，
   站在画面中部偏右的开阔雪地上，避开右侧轿车；脚底加椭圆软阴影"踩"在雪面上。
3. **四边渐隐**：原抠图的发丝顶到了画布左右边缘、脚部到底边，直接合成会留下硬切边。
   所以对底部 70 行、左右各 120 列做 alpha 渐隐，让人物自然淡出融入场景。

### 4.3 重新合成背景

需要换场景或换人物时，按 4.2 的三步重做即可。关键参数：

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `TARGET_H` | 1400 | 人物在场景中的实际高度（场景高 2158） |
| `CENTER_X` | 2350 | 人物水平中心（场景宽 3838），落在**右侧黄金分割线**上 |
| `FEET_Y` | 1990 | 脚底所在高度 |
| `FADE_BOTTOM` | 70 | 底部渐隐行数 |
| `FADE_SIDE` | 120 | 左右渐隐列数 |

关于 `CENTER_X` 的取值：构图按**视口**的黄金分割线（61.8%）而非原图宽度来定，
因为背景用 `background-size: cover`，实际取景框随视口宽高比变化：

| 视口宽高比 | 黄金线对应源图 x |
| --- | --- |
| 16:9（1280×720 / 1920×1080 / 2560×1440） | ≈ 2371 |
| 16:10（1440×900） | ≈ 2327 |

取中值 2350，在两类视口下都落在 61–63% 之间。

注意人物图的不透明包围盒：当前人物是 `(0, 109, 1063, 1890)`，即顶部有 109px 透明边距、
脚在画布底边。换图后要先量新的包围盒，否则落地位置会偏。

### 4.4 CSS 侧的配合

因为人物已经在背景图里，背景的 `filter` 会同时作用到人物，所以滤镜调得较温和：

```css
.player__bg {
  background-size: cover;          /* 铺满，杜绝露边黑框 */
  background-position: center 55%;
  filter: grayscale(0.14) contrast(1.06) brightness(0.92) saturate(0.92);
}
```

另外播放页的暗角（`.fx__vignette`）和冷色分级（`.player__grade`）都做了单独调亮，
避免把画面四周压成黑屏。

### 4.5 图片缺失时的行为

如果 `assets/` 下的图片不存在，页面**不会崩溃**：

- 背景会回退到深色底（`body.fallback-bg`，由 `app.js` 中的 `onerror` 回调添加）；
- 小屏角色缩影自然消失，不影响任何播放功能；
- 相关位置在代码中留有 `TODO` 注释，便于后续补齐。

## 5. 音频实现说明

### 5.1 信号链

```
                    ┌─ 图 A（双耳）: 振荡器L(载波) ─ tone ─ pan(-1) ─┐
                    │              振荡器R(载波+Δf) ─ tone ─ pan(+1) ─┤
                    │                                                │
                    └─ 图 B（等时）: 振荡器L(载波) ─ gate ─ tone ─ pan(-1) ─┤
                                    振荡器R(载波) ─ gate ─ tone ─ pan(+1) ─┤
                                                          ▲           │
                                         LFO(Δf) ─── 0..1 脉冲包络 ────┘
                                                                      │
       粉红噪声 ─┬─ 低通 2.2kHz ─ dither 增益(常开) ────────────────────┤
                 └─ 低通 1.4kHz ─ 噪声增益(可选) ──────────────────────┤
                                                                      ▼
                              主增益(淡入/淡出/音量) ─ 限幅 ─ 分析器 ─ 输出
```

关键设计：

- **双耳节拍**：图 A 左右振荡器频率差 = Δf。默认 200 / 210 Hz → 10 Hz，落在 Alpha 频段。
- **等时节拍**：图 B 左右同频，由 Δf 速率的 LFO 通过 `gate` 做 100% 幅度调制（0↔1 通断脉冲）。
- **两套图常驻 + 交叉淡化**：切模式只改 `tone` 增益，不重建节点。
- **常开舒适底噪 (dither)**：极低电平的宽带噪声，用于压制蓝牙编码噪点，见 5.4。
- **防止过载**：主输出后接 `DynamicsCompressor` 作安全限幅；默认音量下输出 RMS 约 −29 dBFS、峰值约 −26 dBFS，余量充足。
- **后台继续播放**：不监听 `visibilitychange`，切到其他标签页/最小化时照常发声（音频线程不受标签页节流影响）。

### 5.2 无爆音（咔哒声）设计

爆音的根源是**波形不连续**。以下几处是实践中真正会引入跳变的地方，本项目逐一处理：

| 风险点 | 处理方式 |
| --- | --- |
| 在已连通的图里 `stop()` / 新建振荡器重建音源 | **振荡器全程常驻**：`init()` 时创建并 `start()`，之后永不 `stop()`；播放/暂停/换频/切模式只改参数 |
| `AudioParam.cancelAndHoldAtTime()` 高频重设（拖动滑杆时） | 实测会在参数上产生跳变 → 改用 `cancelScheduledValues()` + `setValueAtTime(当前值)` 再叠加斜坡 |
| 暂停后立刻 `suspend()` AudioContext，恢复瞬间电平跳变 | 暂停后**延迟 4 秒**才挂起；从挂起恢复时先把主增益钉在 0，等 120ms 图稳定后再淡入 |
| 换频瞬间赋值 | 频率用 `exponentialRampToValueAtTime` 做 0.6s 滑音（双耳右耳与等时 LFO 同步滑） |
| 切模式时两图相位抵消导致音量忽大忽小 | 先淡出现用图 → 留 120ms 静音 → 再淡入目标图，全程约 0.44s |
| 渲染循环里反复 `new Float32Array()` 造成 GC 停顿、音频线程断流 | 分析器读取缓冲在启动时分配一次并复用；示波器降到 20fps |

暂停/播放的增益变化为 0.9s 渐入、0.55s 渐出，全部使用 sample-accurate 的线性自动化。

### 5.3 如果仍然听到咔哒声

按可能性排查：

1. **蓝牙耳机** —— 最容易被忽略的一条。很多蓝牙耳机进入省电状态时会周期性地"咔"一下，
   与网页无关；换有线耳机或让系统保持有音频播放即可确认。
2. **系统采样率 / 独占模式冲突**（如同时开着 DAW、语音软件、游戏）——
   关掉其他占用音频设备的程序。
3. **CPU 负载过高** —— 浏览器音频线程被抢占时会断流。关掉大量标签页，或把示波器关掉
   （可临时给 `.meter` 加 `display: none`）减轻渲染压力。
4. **音量过大导致限幅器工作** —— 把音量降到 50% 以下。

若确认是网页本身的问题，可把 `audio.js` 顶部的 `SUSPEND_DELAY` 调大或直接禁用挂起
（改成 `return;`），挂起/恢复是浏览器层面唯一可能产生跳变的环节。

### 5.4 蓝牙耳机下的"噪点/沙沙声"

**先给结论：这不是页面产生的噪声。** 实测录下真实输出做频谱分析，各频段的指标是：

| 场景 | 主峰 | 最大杂散 | 5kHz 以上分量 |
| --- | --- | --- | --- |
| ALPHA 双耳 | 199.99 Hz | −68.8 dBc | −96.4 dBc |
| THETA 双耳 | 180.04 Hz | −71.2 dBc | — |
| LOW BETA 等时 | 205.02 Hz | −64.6 dBc | — |

主峰比噪底高约 180 dB（已到 FFT 数值下限），谐波与杂散都在 −65 dBc 以下。
也就是说页面输出的是非常干净的正弦。

**真正的原因是蓝牙编码。** SBC/AAC 是感知编码：对"电平很低 + 频谱极稀疏"的纯正弦，
编码器会判定"没什么可编码的"，于是分配极少的比特，量化噪声就变成了可听见的沙沙声。
这解释了实测中观察到的两个现象：

- 只在放电波时明显 —— 纯正弦最容易被这样处理；
- 加上白噪声后几乎消失 —— 噪声提供了连续信号，编码器分配比特更均匀，同时把量化噪声掩蔽掉。

**针对性的处理**（`audio.js`）：

- **常开舒适底噪 (dither)**：在 2.2 kHz 低通后叠加一层极低的宽带噪声，
  默认音量下输出约 −72 dBFS、比主信号低约 42 dB（接近安静房间的本底声）。
  它一方面让编码器有持续信号可分配比特，另一方面掩蔽残留量化噪声。
- **提高输出电平**：`TONE_PEAK` 从 0.5 提到 0.6，主信号 RMS 由 −31 dBFS 升至 −29 dBFS，
  给编码器更多可用动态。
- **可选 AMBIENT NOISE**：需要更强掩蔽时打开它，会叠加一路 1.4 kHz 低通的粉红噪声，
  电平明显更高（用户实测这一项能基本消除不适感）。

还可从耳机/系统侧改善：

1. 在 Windows 蓝牙设置或耳机 App 里**关闭"增强音频"类选项**，避免二次处理（如杜比/动态压缩）放大编码瑕疵。
2. 尽量使用 **AAC / aptX / LDAC** 而非 SBC —— SBC 在低码率下对纯音的量化最粗暴。
3. 关掉可能对音频做重采样的程序（某些语音/直播/音效软件），避免二次编码。

## 7. 浏览器支持

需要支持 Web Audio API 的现代浏览器：Chrome / Edge 88+、Firefox 90+、Safari 14.1+。
若浏览器不支持，播放页会显示 `AUDIO LINK FAILED`，界面其余部分仍可正常浏览。

页面还遵循 `prefers-reduced-motion`：系统开启"减少动态效果"时，扫描线闪烁、漂移等动画会自动停用。
